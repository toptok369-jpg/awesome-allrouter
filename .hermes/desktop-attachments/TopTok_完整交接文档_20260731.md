### 环境上的坑（会反复踩）

1. **GPU 机没有 `ps` 命令**，找进程要扫 `/proc/[0-9]*/cmdline`。
2. **`pkill -f <名字>` 会匹配到调用它的那条 ssh 命令本身**，把连接杀掉。必须包在脚本文件里执行。
   同理，用 `case` 匹配进程名统计数量时也会把自己算进去。
3. **三条视频线并行会显存不足**，必须串行。
4. **本地 `npx tsc` 是空跑**（appsrc 没装 TS 依赖，会打印 "This is not the tsc command
   you are looking for" 并且**退出码 0**）。唯一真实的类型校验是容器上的 `pnpm build`。
5. **Next 只自动读 `.env` 里的 `NEXT_PUBLIC_*`**，服务端密钥必须在启动脚本里
   `set -a; . /app/.env; set +a` 显式注入。不注入会静默退到代码里的兜底值。

## 2. 角色系统（本轮重点）

### 2.1 三层结构

```
① 人设 persona          文字：她是谁、怎么说话、经历过什么
      ↓
② 拍照人格 photoPersona  文字：她会怎么拍照            ← 本轮新增
      ↓
  ┌──────────────┬──────────────────┐
③ 展示图              ④ 视频资产
  给用户挑角色看        给模型复现同一个人
```

**③ 和 ④ 的要求几乎相反，不能混为一谈**（这是本轮最重要的认知修正）：

| | 展示图 | 视频资产 |
|---|---|---|
| 目的 | 让人想点进去聊天 | 让模型准确复现同一个人 |
| 表情 | 真实微表情、直视镜头 | 中性、闭嘴 |
| 光 | 环境自然光，允许过曝 | 平光，无戏剧阴影 |
| 背景 | 她真实的生活场景 | 纯灰无缝 |
| 形态 | 一张一张分开 | **多角度拼一张**（三视图） |
| 画质 | 手机感，允许不完美 | 最高分辨率、锐利 |

### 2.2 用户建角色的完整流程

```
POST /api/influencers        一句设定 → LLM 写完整人设 + 拍照人格 → DRAFT
POST /api/studio/publish     开唤醒账单（CREATION）
POST /api/payments/{id}      确认支付 → fulfillCreation → generatePortraits（异步 1–5 分钟）
GET  /api/studio/portraits   轮询：返回 { avatarUrl, seeds[], published }
```

注意事项：
- `authedFan()` 要求 **`walletAddress` 非空**，未绑钱包的访客不能建角色
- 建角色 **每 fan 每天限 3 个**（`CREATION_DRAFTS_PER_DAY`）
- `ensureFan()` 在 session 无效时会**静默新建访客并返回 200**，会掩盖鉴权错误；
  只有走 `authedFan()` 的接口才会暴露成 401
- session cookie 格式：`<fanId>.<hmac-sha256(AUTH_SECRET, fanId)>`，不截断

### 2.3 拍照人格（`lib/influencer/photoPersona.ts`）

解决的问题：三张展示图共用一套模板，导致 20 岁跳脱的女孩和 25 岁职场女性
拍出来的构图逻辑完全一样。

七个维度，由 LLM 从人设推导，存在 `lifeContext.photoPersona`：

| 字段 | 含义 |
|---|---|
| `shooters` | 谁按快门（self / friend / stranger / tripod / mirror），带权重 |
| `cameras` | 用什么拍（phone_front / phone_back / phone_flash / old_compact / film），带权重 |
| `subjects` | 她爱拍什么（必须来自具体生活） |
| `places` | 她常去哪 |
| `moodLow` / `moodHigh` | 安静时和高兴时的样子，写具体行为 |
| `wildChance` | 人来疯概率。跳脱外向 0.3–0.45，克制内敛 0.05–0.15 |
| `wildActions` | 放飞时她会做什么 |
| `quirks` | 照片上反复出现的技术特征（手抖糊、过曝、手指挡角） |

出图时 `drawShot()` 带随机性抽一次，拼进提示词，末尾固定加一句底线约束：
`"this is a photo she would actually post herself, not a professional shoot"`。

**实测样本**（沈可星，大学话剧社社长，20 岁出头跳脱型）：
- wildChance **0.38**；自拍 0.34 / 朋友 0.32 / 镜子 0.18；前置 0.38 / **夜里闪光 0.22**
- subjects：涂满红笔批注的独白稿、卡司即兴中的定格、化到一半的舞台妆和服装架
- wildActions：把全组人按住摆成僵住的群像、躺空舞台拍夸张死亡姿势、
  凌晨两点开闪光在厕所镜子前演独白
- 出图后背景确实出现了便利贴、剧本稿、笔筒、后台走廊，第三张是明确的自拍姿势

### 2.4 展示图的亲和力改造

原提示词在规则层面就在推向时尚大片，改掉了三条：

| 原规则 | 后果 | 改成 |
|---|---|---|
| 三张造型/环境/灯光必须互不相同 | 同一角色三张三套衣服，人设场景没被继承 | 三张必须是**同一个人同一天的三个瞬间**，`wardrobeKey` 三张必须相同 |
| 禁止三张都直视镜头 | 把亲和力最大的开关当缺点禁了 | 明确写「直视镜头不是缺点」 |
| （无） | — | 新增亲和力要求：identity 必须直视镜头+真实微表情；至少一张动作到一半被抓拍；优先环境自然光；鼓励生活感的不完美 |

**改完仍未解决服装一致性** —— 见 §5 的硬结论。

### 2.5 视频人物资产（`/root/video_assets.py`）

产物：
- `<角色>-three-view.png` —— 正/3-4侧/正侧/背四视角**逐个生成再横向拼接**
- `<角色>-wardrobe.png` —— 这套衣服的中性全身

生成要求（写死在提示词里）：中性表情、闭嘴、手自然垂放、平光无戏剧阴影、
纯灰无缝背景、全套衣服清晰可见。

**关键实现点：四个视角必须逐个出再拼**，不能让模型"一张图里画四个视角"——
那样会得到四个不同的人。每个视角都以同一张定妆图做身份参考。

### 2.6 dramaclaw 的资产做法（研究结论）

核心概念是 **`visual_state`（视觉形态）**：同一角色可有多套形态（"战神时期"/"皇后宫装"/
"皇后便装"），每套是独立身份资产，**分两层存**：

- `face_description` —— 脸，跨形态不变
- `appearance_details` —— 造型，按形态可换
- 另有 `age_group` / `body_type`

由 `agents/identity_planner.py` 批量规划：筛出场角色 → Pass A 分析默认形态 →
Pass B 分析其它形态 → 落库。

**这一层正好补我们的短板**：我们现在脸和造型混在一起，换场景衣服就跟着变。

## 4. 短剧内容规律（写进了分镜生成器的硬校验）

1. 单集 45–70s / 10–14 镜；第 1 镜必须是视觉钩子；每 15–20s 一次转折；结尾留悬念。
2. 台词 3–5 句，只能落在 turn/climax/cliffhanger 上，**不许复述画面已经看见的事**。
3. **每个道具必须有独占画面的英雄镜头**（只有道具和一只手，没有人脸）。连续两部片栽在这里。
4. 全片至少 3 个不同环境；主角必须有实体动作；相邻两镜画面不许雷同。
5. **严禁在 visual/action 里要求字幕/计时器/UI**。
6. **`continue` 不能接在道具/手部特写后面** —— 上一镜没露脸就没有身份可承接，
   模型会当场编一个人出来。
7. 连续段不超过 3 镜，之后必须回 anchor 重新锁身份。
8. 分镜必须只能从**已生成的**场景板/道具卡里选 id，否则会指向不存在的资产。

## 5. 已验证的硬结论（最重要的部分）

### 5.1 参考图能压住模型先验，纯文字压不住

**同一批对照实验**：
- 视频三视图用图生图（以定妆图为参考）→ **四个视角同一件米白色不对称领上衣，服装完全锁死**
- 展示图用纯文字要求"三张同一套穿搭"→ **出来三套完全不同的衣服**（米白 / 红紧身裙 / 红露背裙）

而且 LLM 端**确实遵守了**（三张的 `wardrobe` 文本都是同一件 `Cream ribbed scoop-neck tank top`），
是出图模型把它渲染成了别的。

**推论：所有一致性（人物、服装、环境、道具）都必须靠参考图，不能靠文字描述。**

### 5.2 LTX 的两个固有行为

1. **有对白时必烧字幕，且字形是错的**（"笔迹"烧成"車坈"）。负向提示词里本来就有
   subtitles/text，但**两个采样器都是 cfg 1 → classifier-free guidance 关闭 → 负向完全失效**；
   正向里写"不要字幕"试了中英文三种写法同样无效。只能后期 `delogo`。
2. **对"女人+素色房间"有强先验**，4 秒内会往那边滑。
   对策：片段提示词必须给**地点的具体文字描述**；只说"和首帧同一个地点"这种
   **指代性**约束顶不住，必须给**描述性**约束。

### 5.3 口型必须由生成视频的模型显式建模

把 TTS 音轨叠到已生成的画面上永远不会有口型，ffmpeg 改不了任何一帧嘴形。
b01 图本来就带 AV 分支（`LTXVSeparateAVLatent` → `LTXVAudioVAEDecode` → `VHS_VideoCombine`），
没台词时只输出 -56 LUFS 底噪；**把台词写进正向提示词**后音轨 -26～-29 LUFS，
whisper 转写与剧本逐字一致，嘴形随音节开合。

**IndexTTS 只用于角色私聊语音，不参与短剧。**

### 5.4 多视角必须逐个生成

不能让模型"一张图里画四个视角"，那样会得到四个不同的人。

### 5.5 delogo 抹字幕的包围盒判据

必须是「亮 + 高频边缘 + 高度不超过画面 11%」三条同时成立：
- 只按亮度 → 把米色衬衫、台灯当文字，框撑到整条带，抹出肉眼可见的糊带
- 加边缘判据后 → 夜景窗外的城市灯点仍会中招
- 再加高度上限 → 才收敛到文字尺寸（69–98px 高）

## 6. 已修的产品缺陷

| 缺陷 | 说明 |
|---|---|
| **付费墙可被完全绕过（P0）** | 锁定内容只有 CSS 打码，`/api/media/<hash>` 无鉴权且 URL 明文写在主页 HTML 里。实测匿名、无 cookie、不过成年门即可取到 PPV 付费图的 1.16MB 原图。已加 `lib/media-access.ts` 服务端闸门；`/api/img` 无权限时强制 blur≥32、w≤320 |
| **付费短剧只交付 5 秒且片中不是本人** | 只发 `clips[0]`，关键帧走裸 t2i。已改为身份编辑关键帧 + 整片拼接 |
| **分镜蒸馏拿回的是"她继续演对话"而非 JSON** | 对白当 user 消息喂进去，模型顺着角色扮演。已围栏成 `<剧情>` 数据 + 末尾重申契约 + 解析失败重试 |
| **私信把上游错误原文当她的消息发出** | 含 LLM 供应商 URL。已改为符合人设的占位且不入库污染记忆 |
| **付费订单渲染中途重启永久卡死** | 渲染是进程内 fire-and-forget。已加 `attempts`/`updatedAt` + watchdog 恢复 |
| **`AUTH_SECRET` 从未注入运行进程** | `pnpm start` 不注入 `.env`，应用一直用代码兜底值 `dev-insecure-auth-secret` 签发 session，`.env` 里的真密钥形同虚设。已在 `rebuild.sh` 加 `set -a; . /app/.env; set +a` |
| **部署脚本静默失败** | 杀进程只等 3 秒，端口没释放时新进程 EADDRINUSE 失败，旧进程继续读被覆写的 `.next`，表现为随机 500。已改为先构建→轮询等端口释放→起服务后必须 `/age` 返回 200 |
| **LLM 单上游 120 秒超时** | 对 4000 token 的结构化输出不够。已按 max_tokens 放大 + 退避重试 + autopilot 保底日程 |

## 7. 记录在案的错误（避免重蹈）

1. **换 LoRA 时沿用了给另一个 LoRA 配的强度**（1.5/3 而非作者的 1/1），
   造成 B 线构图漂移和脸摇摆。**凡是服务器上来的作者参数一律不改；缺件就列清单等补，
   不要自己找替代品配参数。**
2. **成片时长算错**：b01 每段固定 4.04 秒，12 镜 = 48.5 秒，而分镜表写的是 57 秒。
3. **抽帧太稀导致误判**：只抽 4 帧就判 B 线"身份和场景都保住"，
   密集抽 10 帧后发现构图和脸都在漂。**单镜内部的抖动必须密集抽帧才看得出来。**
4. **提示词双语分支不对齐**：有台词的中文分支漏了"保持地点"约束，
   而台词按规则落在关键镜头上，导致后半段系统性丢场景。量化自检查不出来。
5. **`curl -H "age_ok=1; fanId=..."` 少了 `Cookie: ` 前缀**，Cookie 根本没发出去；
   而 `ensureFan()` 会静默新建访客并返回 200，把错误掩盖成"部分接口正常"。
6. **模板字面量相加会被编译器吃掉片段**：`` `a${常量}尾巴` + `b` ``，当所有插值都是
   模块级常量、能被常量折叠时，生产构建会丢掉第一个模板的尾部字面量
   （`video-join.ts` 的 ffmpeg filter 丢了 `:force_original_aspect_ratio=decrease,`，
   删缓存、全量重建都复现）。**这类字符串用数组 `join()` 拼。**
